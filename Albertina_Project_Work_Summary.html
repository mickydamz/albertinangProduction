1. Admin Store Settings Panel

Built a full settings management system so the admin can configure store-wide details without touching code.

What was built

  • Settings database table — a key/value store with seeded defaults (store name, address, phone, email, logo path, delivery enabled, pickup enabled).
  • Setting model — static get(), set(), and clearCache() methods with per-request in-memory caching so the table is only queried once per page load.
  • AdminSettingsController — index() shows the form pre-filled with current values; update() saves changes and handles logo file upload.
  • Admin settings view — two-column form with: store name, logo upload (with live JS preview), address, phone, email, and delivery/pickup toggles.
  • "Store Settings" link added to the admin sidebar navigation.

2. Dynamic Branding Across the Entire Platform

Settings from the admin panel are now automatically reflected everywhere — the storefront, PDF invoices, and customer emails — without any manual code changes.

Storefront (simslayout)

  • Header and footer logos switch to the uploaded logo; fall back to the default image if none is set.
  • Browser tab title uses the live store name.
  • Contact bar (phone, address, email) and footer details are all pulled from settings.

PDF Invoices (DomPDF)

  • Logo is read directly from the filesystem and base64-encoded as a data URI — required because DomPDF cannot resolve HTTP URLs for images.
  • MIME type detected automatically, so PNG, JPEG, or WebP logos all work correctly.

Customer Emails

  • Logo URL built as a full absolute URL (APP_URL + /storage/…) so email clients can fetch it.
  • Footer brand name and support email address are dynamic.

Invoice browser view (invoicelayout)

  • Header logo switches to the uploaded logo with a fallback to the default asset.

Admin panel (adminlayout)

  • Sidebar brand name and page titles use the live store name.

3. Post-Login Redirect Fix

Previously, logging in always sent users to their role's dashboard even if they had been trying to access a specific page before being asked to log in.

  • Changed all role-based redirects in LoginController to use redirect()->intended().
  • Laravel stores the originally-requested URL in the session; intended() sends the user there first, falling back to the role dashboard only if no prior URL was stored.
  • Applies to all roles: admin, supplier, affiliate, manager, and regular customer.

4. Banner Click Navigation

Banners on the customer homepage were already stored with a link field in the database but clicks had no effect.

  • Wrapped each banner image in an anchor tag pointing to $banner->link.
  • Opens in a new tab (target="_blank") with safe rel="noopener noreferrer" attributes.
  • Only renders the anchor when a link is actually set; banners without a link are unaffected.

6. Bug Fixes

Blade parse error — contact bar in storefront

  • Cause: Inline @if/@else/@endif blocks where the fallback text started with a digit (e.g. @else17-18 Zik's…) — Blade parsed @else17 as an unknown directive.
  • Fix: Split all conditional blocks onto separate lines in simslayout.blade.php.

Settings form showing empty defaults

  • Cause: Migration seeded null values for address/phone/email.
  • Fix: Updated migration seed with real default values; existing installations patched via Artisan tinker.

Autoload crash — BankAccount model not found

  • Cause: BankAccount model file was deleted but six files still imported it.
  • Fix: Removed all imports and usages across CartController, AdminController, Country model, PaymentMethod model, UserController, and User model.
